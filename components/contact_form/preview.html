Values the spec didn't give — my inferences

  • Field text size: 20px. Only the title (24) and slogan (40) had char_size. Correct me and it's one variable.
  • Privacy text size: 14px. Same reason.
  • Field width: 441px (84% of its column). Derived from the gap between the field column at x:645 and the textarea at x:1170, keeping the 84px page margin as the gutter.
  • Placeholder colour lifted to #9E9E9E. The spec's #616161 is the line colour; used as text on #292929 it hits 2.6:1 contrast, below the 4.5:1 minimum. The lines stay exactly #616161. This one I'd push back on — it's a legibility bug, not a taste call.
  • Corner radius 66.5 on a 62-tall button is greater than half the height, so it renders as a pill. Used 999px, same result, no rounding artefacts.
  • Textarea radius: 20px (--radius-box). The spec gives no radius for the Richiesta box — give me the number from Figma and it's a one-line change.

Things I changed on purpose

  • Split checkbox.svg into two paths. The file draws the box and the tick as one path — shipped as-is, the box looks permanently ticked. Box is always visible, tick fades in on :checked.
  • Real <label> on every field, visually hidden. Placeholder-only fields leave screen readers with nothing and lose the label the moment someone types. Design is unchanged.
  • Honeypot field added (name="website", off-screen). As agreed: no captcha. The server rejects any submission where it's filled.
  • Consent is required and unchecked by default. Non-negotiable — it's the legal basis for sending the mail.
  • Message field is optional, matching the spec: it's the only placeholder with no *.
  • Mobile (<900px) unspecified: single column, full-width button at 56px tall for thumbs.
  • Field focus is the line itself — no outline box. It goes white and thickens to 2px, and the padding drops by the same 1px so the text doesn't shift. Still a visible focus state for keyboard users, which is the part that can't be dropped.
